A multiple linear regression analysis was conducted to predict hourly bike sharing demand (cnt) based on 18 meteorological, cyclical harmonic, and calendar features. The overall regression model was statistically significant, F(18, 10408) = 1343.35, p < .001, accounting for 69.91% of the variance in rental demand (R² = .699, Adjusted R² = .699). Working day rush hours (is_rush_hour: B = 164.92, SE = 2.57, β = .391, t = 64.26, p < .001) and ambient temperature (temp: B = 280.08, SE = 35.27, β = .411, t = 7.94, p < .001) were the most influential positive predictors. Multicollinearity diagnostics revealed severe variance inflation between temperature and feeling temperature (VIF_temp = 92.47, VIF_atemp = 75.97), which was strategically addressed through Lasso (L1) regularization that eliminated redundant atemp. Under distribution-free split conformal prediction on an independent calibration set (n_cal = 1,737), the empirical coverage reached 94.40% on future unseen test data at the nominal 95% confidence level.

CRISP-DM 六大階段完整實作

從商業痛點定義、探索性數據分析、防外洩特徵工程、建模選取到部署架構，層層嚴謹把關。

階段一：業務理解 (Business Understanding)

營運痛點量化

共享單車營運的「雙重不對稱成本」痛點：

  • 低估需求 (Under-prediction)：站點無車可借，引發消費者民怨、降低通勤滿意度並造成營收永久性流失。
  • 高估需求 (Over-prediction)：調度卡車盲目投放過多車輛，車樁爆滿導致抵達用戶無法還車，且空車閒置耗損折舊。
專案核心目標：建立兼具「高解釋性（清楚掌握各氣象與行事曆因子權重）」與「統計保證（95% 預測區間）」之小時需求模型，提供調度中心具體防護區間。

跨站車輛再平衡 (Fleet Rebalancing)

以預測上限 $Upper_{95}$ 作為「最大備車容量」，以預測下限 $Lower_{95}$ 作為「最小車樁保留容積」，實現精準智慧派車。

階段二：資料理解與探索性分析 (Data Understanding & EDA)

17,379 筆觀測值

數據特徵深度探勘發現：

  • 無缺失值：全資料集 17,379 筆小時紀錄無任何缺失。
  • 嚴重共線性 (Multicollinearity)：溫度 `temp` 與體感溫度 `atemp` 之相關係數高達 0.9877！為後續特徵選取的關鍵考驗。
  • 雙峰通勤 vs 平緩單峰：工作日借車呈現強烈 08-09 與 17-18 時之早晚雙尖峰；假日則轉變為午後悠閒單峰。

階段三：資料準備與防範外洩 (Data Preparation & Leakage Prevention)

18 個工程化特徵

嚴格防範資料外洩策略：

  1. Target Leakage 絕對防範：強制移除 `casual` 與 `registered`，因其數值加總直接等於目標變數（$cnt = casual + registered$）。
  2. 移除純流水號：剔除 `instant` 避免模型記憶遞增索引。
  3. 嚴格依時序遞增切分 (Chronological Split)：
    • 訓練集 (Train): 前 60% (10,427 筆，2011/01 ~ 2012/03)
    • 驗證集 (Val): 次 15% (2,606 筆，2012/03 ~ 2012/07) - 特徵選取專用
    • 校準集 (Cal): 次 10% (1,737 筆，2012/07 ~ 2012/09) - 共形區間專用
    • 測試集 (Test): 末 15% (2,609 筆，2012/09 ~ 2012/12) - 未來獨立評估
  4. 特徵工程：構建 24h 日諧波 (`hr_sin`, `hr_cos`)、12h 通勤半日諧波 (`hr_sin2`, `hr_cos2`)、工作日尖峰交互項 (`is_rush_hour`) 與溫濕度交互項 (`temp_hum`)，共 18 個特徵。
特徵工程關鍵算式
# 24h 日週期諧波
X['hr_sin'] = sin(2 * π * hr / 24)
X['hr_cos'] = cos(2 * π * hr / 24)

# 12h 半日尖峰諧波 (捕捉早晚雙峰)
X['hr_sin2'] = sin(4 * π * hr / 24)
X['hr_cos2'] = cos(4 * π * hr / 24)

# 工作日尖峰指示器
X['is_rush_hour'] = (workingday == 1) & 
                    (hr.isin([8, 9, 17, 18]))

階段四：多元線性迴歸與五種特徵選取 (Modeling & Feature Selection)

5 種演算法全面對決

特徵選取演算法實施細節：

  • Lasso (L1)：以 5 折交叉驗證自適應懲罰，在 `temp` 與 `atemp` 共線性中自動壓縮 `atemp`。
  • Forward SFS：前向貪婪逐步迭代，以最小訓練 RSS 為指引。
  • RFE：依據線性模型權重遞迴淘汰次要特徵。
  • ElasticNet (L1+L2)：展現分組效應，同時保留並分攤高度共線之 `temp` 與 `atemp`。
  • Exhaustive Search (窮舉搜尋, k=1..6)：矩陣化加速，在 3 秒內遍歷 31,179 種組合，求出全域數學最優解！
